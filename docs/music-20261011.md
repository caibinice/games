2. 使用 [librosa 的 REPET-SIM 背景 / 前景分离方法](https://librosa.org/doc/0.10.2/auto_examples/plot_vocal_separation.html)：2048 点 STFT、256 点步长；比较相隔至少两秒的 24 个相似谱帧，以中位数估计重复音乐，2.5 倍 margin 的 soft Wiener mask 抑制非重复的点击、移动、消除等前景音。第二段录屏补充音乐参考。保留原音乐相位，未替换成合成旋律。
3. 抓鹅裁取 0.4～41.4 秒；拼豆裁取 0.5～43.5 秒；首尾一秒余弦交叉融合，旋转融合区到文件内部，循环接缝是原本相邻的样本，不是每轮淡出到静音。
4. 响度归一化，PCM 峰值最多 -2 dBFS；导出带 Xing / LAME gapless 信息的 44,100 Hz、96 kbps 单声道 MP3。抓鹅成品解码 RMS -22.44 dBFS / 峰值 -4.53 dBFS；拼豆 RMS -24.00 dBFS / 峰值 -2.44 dBFS。游戏内另乘 0.55 音量，给操作音效留空间。
5. 分离是对混合录音做谱域抑制，并非拿到了无音效的母带。被移除的总能量比例约 43.6% / 51.8%，其中也可能包含部分音乐瞬态，这个指标不等于音效消除率。数值验证不替代真人听感验收。

## 维护与重做

运行时：`games/<id>/public/music.mjs` 和 `games/<id>/public/assets/audio/music-loop.mp3`；播放器有独立副本，无跨游戏导入。使用 [Web Audio 的 AudioBufferSourceNode 循环](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/loop)，解码一次后重复 PCM，不在每次循环发请求或重新创建 source。首次手势中先 resume AudioContext，再异步读取文件；与操作音效共享 context。

离线处理脚本 `scripts/prepare-music.py` 与 `scripts/audio-requirements.txt` **不是构建 / CI / 发布依赖**。在 E 盘任务环境安装可选依赖，不改全局 Python：

```powershell
Set-Location E:\codes\games
$work = 'E:\Documents\AI\codex\tmp\music-preparation'
& .\.venv\Scripts\python.exe -m venv "$work\venv"
$python = "$work\venv\Scripts\python.exe"
& $python -m pip install -r scripts/audio-requirements.txt
$ffmpeg = 'PATH_TO_FFMPEG_7_1.exe'
$videos = 'C:\Users\caibin\AppData\Local\UUYC\GameViewer\Download'
& $python scripts/prepare-music.py --source "$videos\2.mp4" --reference "$videos\1.mp4" `
  --ffmpeg $ffmpeg --work "$work\goose" --start .4 --end 41.4 `
  --output games/goose/public/assets/audio/music-loop.mp3
& $python scripts/prepare-music.py --source "$videos\3.mp4" `
  --reference 'E:\Downloads\Screenrecording_20261004_210500.mp4' `
  --ffmpeg $ffmpeg --work "$work\pindou" --start .5 --end 43.5 `
  --output games/pindou/public/assets/audio/music-loop.mp3
```

替换音乐时更新两个入口的版本号和各自音频 URL 查询版本，记录来源，重新检查成品解码时长、峰值和接缝。首次加载失败、解码失败、手机暂停 AudioContext 都不影响操作；下次有效触摸会重试，关闭音乐或打开弹窗时正在加载的音频也不会突然播放。
